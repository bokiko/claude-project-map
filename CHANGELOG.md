# Changelog

## 3.4.0 (2026-10-11)

### Added
- **What changed since the previous assessment, first.** Coming back to a project meant re-reading chats. The page now opens with a "Since the previous assessment" section (between the header and the tiles) and the session-start brief carries the same facts: how many commits landed and how many files are uncommitted since the map was last judged (counted by the scripts against the previous assessment, never against "your last visit"), up to three changes in plain words, the one thing that deserves attention, and what the map could not check. Each change says `landed, not checked by the map` or `uncommitted`; the map never says "checked", because a four-call update cannot show that something works. A change is called landed only with a commit that really exists (or, in a project without git, a real file).
- **A decision always comes first.** While a decision waits for you, it is the attention item; the judgement is rejected if it says "work can continue" instead. If an answer or a deferred closure changes which decisions are open between the judgement and the publication, the scripts correct the attention themselves and keep the model's original under `attention_judged`; an answered decision is never shown as one that still needs you.
- **The map says what the model saw.** Each pack now records what it left out (commits listed of commits total, uncommitted files, cut decisions, dropped answers, a cut ledger, dropped repositories, changed watched files that were trimmed away), measured on the pack the model actually read. When relevant work was omitted, the page and the brief say so ("40 of 60 commits shown to the model") instead of pretending the batch was complete.
- **One honest answer to "does anything need me?"** A single script-owned check (`state.assurance`) now decides the wording of the page pill, the "Needs you" tile and the brief: `Needs you` when a decision is ready, `Nothing needs you` only when nothing is open and the assessment is complete, otherwise `No decision identified in the checked information` with the reasons (a stale assessment, partial coverage, unverified tags, attention that is not "continue", omitted work). A session-start brief produced when facts ran out of budget is no longer shown as fresh: the hook says `project-map: facts not refreshed (budget); run /project-map`.
- Contract: `docs/INTERFACES-3.2.md` section 13. The state schema stays `project-map-4` (additive fields: `since`, `judged_seen`, `assurance`, `status.git_error`); older maps still render and say so until their first 3.4 judgement.

### Changed
- **Brief layout.** Line 2 is now `as of <snapshot minute> · assessed <judged minute> · current` or `behind: <why>`, followed by the first reason the assessment is incomplete when nothing needs you. New lines: `attention: ...`, `since <minute>: N commits · M uncommitted · k changes` and up to three `- <change> · landed, not checked | uncommitted`. The release line (`git: ...`) now sits below the next step and the overtaken-by-events lines. Lines are still whole, at most 1000 bytes, and are dropped in a fixed order (tokens, git, changes, since, attention, overtaken, stale/coverage) before the decisions collapse into `+N more decisions`; the next step and the generation line are never dropped. A very long folder is shortened to 60 bytes.
- **A watched path added during an update counts toward coverage.** When the update adds a path to the watch list, the publish step checks it on the spot; if that check cannot finish, the map shows coverage partial instead of "Nothing needs you".
- **Pill.** A stale map with an open decision now says `Needs you` (before: `Assessment may be out of date`); the out-of-date warning is its own line under the project metadata.
- Agent prompt and FULL run: the `since` rules (a consequence, not a commit subject; no "checked"; a decision is always the attention item; never "continue" when the pack cut work). Judgement size target 3.5 KB, hard limit unchanged at 6 KB.
- Existing tests that asserted the old brief layout were updated (E-brief line 2, F-stale-refresh, REL-brief); a Node DOM shim (`tests/pm_page.js`) lets the suites run the page's own JavaScript.
- Suites: guard 1053, git 416, embed 1314, hooks 139, usage 215 (3137 cases, five suites), each under `bash` and `/bin/bash` 3.2. Every new rule was mutation-checked (59 deliberate breaks of the code, each caught by a named test).

## 3.3.0 (2026-10-10)

### Fixed
- **The session-start brief and the plugin-update refresh never worked.** Hooks run with `CLAUDE_PLUGIN_DATA` set, the skill's own facts/embed calls do not, and the signing key was chosen by that variable, so the hooks checked every map against a different key and rejected it. There is now one key location for every caller (`~/.claude/agent-memory/project-map/key`, unreadable to the map agent); maps signed at that location verify again. Maps signed by a hook with `CLAUDE_PLUGIN_DATA` set (the old `DATA/key`) are recovered by an authenticated legacy path: the first time a hook sees one, the old key must authenticate its manifest and every file must match, then it is re-signed with the canonical key (an existing canonical key is never replaced; unsigned or tampered maps are never adopted). Without that old key the map is unverified and needs one FULL run. Regression tests K-one-key and C330-7.
- **The hook refresh failed for every heavy Claude user (`PM_EMBED_ERROR deadline`), and the skill paid a 4-7 s scan.** `project-map-usage.py` read and parsed every transcript under `~/.claude/projects` and `~/.codex/sessions` (1.1 GB here, 4-7 s) on each collection; the UserPromptSubmit refresh runs with `--deadline 3.5` and gave the scan the whole remaining budget, so it timed out, the refresh failed and usage was retried on the next one, forever. Now: (1) the scan is incremental, with a per-root cache in `.project-map/usage-cache.json` and `usage-last.json` (a transcript with the same size and mtime is skipped, one that only grew is read from the old end after its first and last 4 KB are verified, deleted files drop out, a changed or rewritten one is re-read; totals are exactly those of a full rescan), and it takes `--budget S`: out of budget it saves its progress and returns the previous totals as `partial` with the as-of time of the last complete scan. (2) Usage can no longer fail a refresh or a verdict: mechanical embed gives it only what is left of the deadline minus a render margin, and a timeout, crash or partial scan keeps the previous numbers marked `stale` with their original as-of time ("usage as of 2026-10-10 15:46" in the brief and the page) and publishes anyway; it is retried on the next refresh (the one-hour rule now looks at the usage's own as-of time, not the map's). Facts (the skill path) gives the scan at most 10 s and keeps the previous numbers the same way, so a judged publish does not lose them. Measured on this machine: warm `project-map-facts.py` 3.8 s to 0.37 s (0.31 s without usage), warm usage script 3.3 s to 0.04 s, a cold first scan 2.1 s; `--mechanical --deadline 3.5` with the old 2 h usage and a cold cache: error before, `PM_EMBED_OK` after. Contract: `docs/INTERFACES-3.2.md` section 11. Regression tests: the new suite `tests/test_usage.sh` (incremental equals full rescan, cache reuse, partial and resume) and U33-* in `tests/test_embed.sh` (mutation-checked against the old behaviour).
- **Usage cache: private location, counters only (Codex audit U330-1 to U330-6).** (1) The incremental usage cache held transcript-derived text (a Codex user-message excerpt, Claude ai-titles, other projects' working directories, transcript paths as keys) in `.project-map/`, which the map agent can read. It now lives in the plugin's private directory `~/.claude/agent-memory/project-map/usage/` (mode 0700, files `<sha256 of the real root>-cache.json` and `-last.json`, mode 0600; the guard denies the map agent that directory), a legacy `.project-map/usage-cache.json` / `usage-last.json` is deleted on sight, and everything that leaves the script (stdout, snapshot, pack, state, page, brief) goes through a counters-only allowlist: per-model totals, per-job token rows, counts; a job label is the ai-title only for a session that ran in the project folder itself, every other label is `Claude session <id8>` / `Codex session <id8>`; user messages, transcript paths, foreign cwds, subagent descriptions are never output and Codex user text is no longer even cached. A stored usage from an older build loses its free-text job labels when reused. (2) A middle edit was missed (a same-size file with a new mtime, or a grown file whose two 4 KB windows still matched, kept the old total for good): a same-size change of mtime now re-reads from byte 0, and a grown file's whole old prefix is verified by a streamed hash. (3) A file rewritten while it was scanned could be sealed with the other version's hash and cached as attributed: size, mtime and inode are compared before and after, a changed file is dropped from the run (previous entry kept, run `partial`) unless it only grew and its committed prefix still hashes the same. (4) The cache cap is real: completed files lose their parse state and are evicted least-recently-seen first, a file still being scanned is never evicted (the old eviction reset a half-parsed file to byte 0 on every run, so a small cap never finished); a cap that cannot be met is reported as `scan.cache_partial` and not written. (5) The atomic write used a predictable temp name that was opened without O_EXCL (a planted symlink was followed, a planted file kept its mode): now `mkstemp` in the cache directory, `fchmod 0600`, fsync, rename. (6) `--budget` bounds the whole run: cache load, enumeration, huge lines, and the final certification (a one-record run that overran on its last chunk returned `partial: false`). Measured on this machine (815 transcripts, 1.15 GB): cold scan 3.2 s, warm 0.02 s (0 bytes read), 20 s later with live sessions growing 0.03 s (5.9 MB read: the grown file's old prefix is hashed once). Regression tests: U330-* in `tests/test_usage.sh` and `tests/test_embed.sh`; `tests/test_git.sh` now uses a `mktemp` scratch directory (parallel runs collided and left a `scripts/scripts` link). Contract: `docs/INTERFACES-3.2.md` section 11.
- **Usage scan progress survives a budget and a small cache (Codex round 2, U330-R2-2 and U330-R2-3), and the staged judgement no longer carries retired decisions.** (1) Verifying the old prefix of a grown transcript started from byte 0 on every run, so a prefix that did not fit one budget never finished. The prefix is now fingerprinted in fixed 1 MB blocks (a chained digest of full blocks plus a hash of the last partial block); after every block the verified position and chain digest are saved, bound to the file's device/inode/size/mtime snapshot, and the next run continues from them. Any other state of the file starts over, and the final fingerprint must still equal the committed one, so rewrite detection is unchanged. (2) Evicting a whole completed file under the cache cap discarded its work, so a run that could scan only a few files per budget never reached the rest. A completed file that no longer fits is now folded into a compact record keyed by its path hash (size, mtime, flags, job rows); the aggregate is folded bucket plus live entries, an unchanged folded file is reused without being opened, a changed one is read again, and only a bucket that itself does not fit loses its oldest records. A scan cursor (per source, where the last budgeted run stopped) makes the next run resume there and wrap around. (3) `project-map-facts.py` stages `judgement.in.json` without the decisions retired in the pinned state (a mechanical refresh retires closed ones and their ids are never reused), so an agent that copies `decisions[]` from it no longer trips `decision id D-00N was retired`; nothing else in the file changes. Contract: `docs/INTERFACES-3.2.md` sections 11 and 12.8. Tests: U330-R2-* in `tests/test_usage.sh`, STG-* in `tests/test_embed.sh` (mutation-checked).
- **Usage cache: identity, foreign transcripts, collisions, pressure (Codex rounds 3 and 4, U330-R3-1..3, U330-R4-1..2).** (1) A settled transcript that belongs to another project now folds into the compact bucket with zero rows; before, such files could never fold, so under a cap they were evicted whole and rescanned forever (a heavy user has hundreds of them). (2) "Unchanged" now means size, mtime_ns AND file identity (device, inode, ctime_ns) for live entries, folded records and the verification snapshot: a rename-over or an in-place rewrite that restores mtime_ns is read again from byte 0 (ctime cannot be set from user space; a chmod/touch of an unchanged file costs one extra read). (3) Folded records are keyed by the first 24 hex digits of the path's SHA-256 and store the rest of the digest; reuse requires it, so a key collision re-reads instead of handing one file another file's rows. (4) `scan.cache_pressure` and `scan.evicted_records` report when compact records had to be dropped to meet the cap; budgeted runs converge only while the cap holds the compact records (about 370 bytes per attributed transcript, 200 per excluded one; the default 24 MB holds roughly 65k attributed or 100k excluded transcripts), an unbounded scan always completes. Cache schema `project-map-usage-cache-5` (older caches rebuild once). Test hooks `PM_USAGE_BLOCK`, `PM_USAGE_PKEY_LEN`. Tests: U330-R3-*, U330-R4-* in `tests/test_usage.sh` (mutation-checked).
### Added
- **The map sees tags and pushes.** After a release was committed, tagged and pushed, the map still said "next: tag and push" because the facts never contained tags or branch sync state. Each repository now records, from local refs only (no fetch, no network, no assumption about tag names, remote name, default branch or SemVer): the tags that point at the pinned HEAD (lightweight and annotated), the five newest tags (display only) and the branch's upstream state (`aligned`, `ahead`, `behind`, `diverged`, `no_upstream`, `missing_upstream`, `detached`, `unborn`, `unknown`, with ahead/behind counts that are `null` when unknown). A sub-folder of a larger repository shows the shared repository's state and says so; nested standalone repos have their own.
- Wording is local evidence only: `tagged v3.2.3 at HEAD · in sync with origin/main (local tracking state)`, `3 commits ahead of origin/main`, `no upstream`. The map never says "released" or "pushed", and never infers review approval from tags. Pack (reserved ahead of optional details), brief (one `git:` line after the headline, below decisions and next step) and page (under the folder line, textContent only) carry it.
- Change detection: a new `release` key (head-tag identities, upstream ref, sync state, ahead count; not the behind count or recent tags). A tag-only or push-only change gives `NEEDS_JUDGEMENT tags changed` / `branch sync changed` even with no new commit; a behind-only change is a mechanical refresh once, never a loop. A map judged before 3.3.0 is re-judged exactly once. If tags or sync move while a judgement is being written, the map is published flagged stale and the next run re-judges.
- Agent prompt: one rule to use the release line and drop "tag"/"push" next steps that the facts already show done locally; remote publication, deploy and review stay unknown unless evidenced.
- **Decisions overtaken by events.** The map raised "tag v1.0.0 and push now, or wait?" (a hard-rule decision); the owner tagged and pushed by hand; the next update's facts said so, yet the decision stayed under "needs you" - and a decision the model simply left out of its judgement vanished without a trace. Now a decision can carry a closure predicate bound when it is RAISED: `resolves_when` (1-3 predicates, all must hold: `tag_at_head{repo,name|null}`, `branch_in_sync{repo}` (state `aligned`), `commit{repo,sha}`, `file{path,exists}`), validated at raise (well-formed, repo in the snapshot, path inside the project) and script-owned from then on (the model cannot add or change it later). The script evaluates it against the staged snapshot and shows the verdict to the model as `decisions[].resolved` in the pack. The model may close an open or overdue decision with `overtaken{why <=120 bytes, ref optional}` ONLY when the script says every predicate holds; `why` is an explanation, `ref` (if given) must be one of the checked evidence strings. A decision without `resolves_when` is closed only by the owner's answer. The state record is a verbatim copy of the STAGED decision (question, options, hard rule, default, deadline, `resolves_when`) plus the script-owned `status:"overtaken"`, `closed_by:"events"`, `closed_at`, `overtaken_why`, `overtaken_ref`; whatever the model wrote for that id is ignored. It is shown for one generation, also across mechanical refreshes (a refresh now drops the closed decisions of the pinned generation exactly as a judgement does, and a not-yet-applied answer is never lost), brief line `D-001 overtaken by events: <why> (<evidence>)` (not a "needs you" line), a "Resolved by events" panel, a history entry. A hard-rule decision can be overtaken: the action already happened by the owner's hand, and the map still never authorizes, defaults or records an answer for it (`answers.jsonl` stays the owner's record). Owner answers win: embed re-reads `answers.jsonl` under the publish lock, and an answer appended after the facts for a decision the judgement closes is published as `answered` (the closure is dropped, the answers appended meanwhile are applied in file order, `PM_EMBED_NOTE` says so, the next verdict re-judges); other answers appended during a judgement stay pending as before. Retired decision ids are tombstoned for good in `state.retired_decisions` (a compact range string, never truncated; the 200-id `retired_ids` window stays for part ids), so a decision id can never be raised again. Never-vanish rule: a judgement that omits a decision that is open or overdue in the previous state is rejected. The unused `withdrawn` status is gone. Contract: `docs/INTERFACES-3.2.md` section 12 (and 6.2, 6.4, 6.5, 6.6). Tests: OV-* in `tests/test_embed.sh` (mutation-checked: each of twelve mutants of the validator, merge, pack, answer-precedence and mechanical code fails them).
- **Codex round 1 (C330-1 to C330-7).** A failed, timed-out or unavailable release recheck at publish time is flagged stale (unverified) instead of passing as no change, and an exhausted deadline fails on the deadline path; the complete head-tag set is streamed, counted and hashed (display capped at 20; a truncated read is reported partial and never NO_CHANGE); a sub-folder publish compares path-scoped activity, not raw repository HEAD; the configured upstream is pinned as a literal ref and symbolic HEAD, upstream config and upstream oid are re-checked (unknown on a race); `missing_upstream` and `unborn` need a narrow existence query, malformed refs give unknown; tag, branch and upstream names are shown escaped or redacted (raw identities stay internal); legacy DATA-signed maps are recovered (see Fixed).
### Security
- `pm_git.py` accepts the new commands (`for-each-ref` x4, `symbolic-ref --quiet HEAD`, `rev-parse --verify --end-of-options HEAD^{commit}` / `<literal refs/remotes|heads ref>^{commit}` / `--is-shallow-repository`, `rev-list --left-right --count <oid>...<oid>`) as exact argv tuples only (full 40-hex oids, literal `refs/heads/<branch>` that passes ref grammar, no wildcard or control characters). `pm-git.sh` and the agent grammar are unchanged and refuse them; no blanket non-zero exception was added for any subcommand.
- Contract: `docs/INTERFACES-3.2.md` section 10. State schema stays `project-map-4` (additive fields).
- **Codex round 2 (C330-R2-1 to C330-R2-5).** (1) Any partial tag recheck at publish time is flagged stale (unverified) on its own, whatever else is equal; a complete-to-partial transition (a tag past the row limit appearing during judgement) is named, instead of slipping through because the retained digest was equal. (2) An unchanged partial tag key is a script-owned coverage warning, not a semantic change: no more paid `NEEDS_JUDGEMENT` on every run for a repository with too many tags at HEAD (facts -> UPDATE -> one refresh -> `NO_CHANGE`); a changed prefix, count, sync or coverage still re-judges, and the warning ("tag list incomplete") stays in the release line, brief, state and page, never a bare "complete". (3) The final pin re-read keeps query success separate from absence: a timeout or error on the last HEAD, symbolic-ref, upstream-metadata or upstream-oid read is re-read (twice at most) and then `unknown`/`inconsistent`, never a silent `no_upstream`, `detached` or `missing_upstream`. (4) The scoped activity recheck also runs when the package had no commit of its own at judgement time: its first commit landing during judgement is stale; parent-only commits stay quiet. (5) Legacy-key recovery writes the canonical publish record of the owning root with the final manifest hash after re-signing (never for an unauthenticated map), so losing the canonical key later does not force a FULL run.
- **Codex round 3 (C330-R3-1, C330-R3-2).** (1) The final pin re-read no longer equates a failed `rev-parse` (rc 1/128) of HEAD or the upstream with absence: it goes through the same exact existence/type query as the first read, and the answer (`absent`, `commit`, `other`, `broken`, with a timeout as unverified) is part of the pin. An absent upstream that becomes a ref to a tree or a missing object, or an unborn branch that gains a broken ref, during the final read is now a mismatch (re-read, then `unknown` with null counts; `inconsistent` if it keeps flipping), never `missing_upstream` or `unborn`. (2) When re-reads are exhausted, tag coverage is UNKNOWN, never "no tag at HEAD": a tag set read for a HEAD oid that the last read verified unchanged is kept, otherwise `head_tags` is `null` and the line reads `tags unknown · sync unknown`. The release key carries `unverified`, so an unchanged inconsistent state stays script-owned (one `NEEDS_REFRESH stale cleared`, then `NO_CHANGE` with the warning, no paid judgement), and `light_stale` flags any inconsistent publish-time recheck as unverified even when its key equals the judged key.
- **Codex round 2 (decisions) (OV330-R2-1 to OV330-R2-5).** (1) The staged answer prefix (line count and hash) is verified before an owner answer can win at publication, also when nothing was appended: a same-count rewrite (a staged line replaced by a hold for the closing decision), a truncation or a deleted file is `PM_EMBED_ERROR`, and an unreadable `answers.jsonl` is an error rather than an empty file. (2) Only complete, newline-terminated lines of `answers.jsonl` are read, counted, hashed and applied (facts and embed): an unfinished concurrent append stays pending, is not bad input and never poisons the prefix hash, so completing it later is an ordinary append and not "answers rewritten". (3) Tag predicates bind a stable identity: every head tag carries `tid` (16 hex of the sha256 of its raw ref name), the predicate stores the `tid` resolved from the display name at raise (ambiguous display names such as two `[redacted]` tags, and escaped names that are not at HEAD, are rejected) and evaluation compares identities, so another tag with the same display, or a bidi tag that is no longer at HEAD, can no longer satisfy it. (4) `exists:false` checks the directory entry (`lstat` of the confined original path), so a dangling symlink is an entry that exists; filesystem errors are unknown (not satisfied, with a reason). (5) Repository predicates re-confine the recorded repo path at raise and at every evaluation (realpath inside ROOT, still its own git work tree); a path swapped for a link to an outside repository fails closed with `repo path escaped or changed; refresh facts`, and `cat-file` runs only in the confined directory. Contract: `docs/INTERFACES-3.2.md` sections 6.7 and 12. Tests: OV-R2-* in `tests/test_embed.sh` (mutation-checked against the previous code).
- **Codex round 3 (decisions) (OV330-R3-1 to OV330-R3-3).** (1) The pack no longer shows the internal tag identity anywhere: `tid` is stripped from every `decisions[].resolves_when` predicate after the script computed `resolved` / `resolved_why` from the bound predicates (the snapshot and state keep it), so a carried named-tag predicate copied verbatim from the pack is the predicate it was raised with and no longer fails with "resolves_when is fixed when the decision is raised". (2) A future tag name (one not at HEAD yet) must be a legal git tag name at raise: the rules of `git check-ref-format refs/tags/<name>` are checked in Python (`..`, leading `.`, `.lock`, space, control characters, `~ ^ : ? * [ \`, `@{`, trailing `.`, lone `@`, empty components) and confirmed by the real git through a script-internal exact tuple (`check-ref-format refs/tags/<name>`, refused by the agent wrapper); a name git can never create is rejected instead of producing a predicate that can never hold. (3) An uncommitted last line in `answers.jsonl` (no newline) no longer lets a closure by events race the owner's answer: at publication the closure is deferred (the decision is published still open, `judged_key.closure_deferred`, `PM_EMBED_NOTE uncommitted answer tail; events closure of D-00N deferred`), the next facts run re-judges once the tail is committed or removed, partial bytes are never applied or hashed, and the facts verdict line warns `answers.jsonl has an uncommitted last line`. A committed late answer still wins as before. Contract: `docs/INTERFACES-3.2.md` sections 6.7 and 12. Tests: OV-R3-* in `tests/test_embed.sh` and the `check-ref-format` cases in `tests/test_git.sh` (mutation-checked against the previous code).
- Codex round 4 (decisions, OV330-R4-1): the unterminated-tail flag and the late owner answers now come from one read of `answers.jsonl` (`late_answers(image=...)`), so a record committed between two reads can no longer be seen by one check and missed by the other. Test OV-R4-1.
- Suites: guard 1053, git 416, embed 1128, hooks 129, usage 215 (2944 cases, five suites), each under `bash` and `/bin/bash` 3.2.

## 3.2.3 (2026-10-10)
### Changed
- **Any project folder in your home folder works.** 3.2.2 only mapped projects under `~/projects`, `~/Desktop` or `~/thoughts`, so a project in `~/code` or `~/dev` failed after the facts step. The guard now accepts any folder inside `$HOME` except the home folder itself, hidden top-level folders (`~/.config`, `~/.ssh`, `~/.claude`, ...) and `~/Library`; Claude scratchpads stay allowed. Paths are resolved first, so a symlink into a hidden folder is refused; the exclusions are compared case-insensitively (macOS accepts `~/library` for `~/Library`), and `$HOME` itself is resolved, so a trailing slash or a symlinked home still works. Every other guard rule is unchanged. Codex review: AGREE after round 2 (round 1 found the casing bypass and the home spelling issue).

### Security
- Guard: it parses its whole input linearly; the main session is never denied for size; for the map agent a Bash command over 2 KB or an input over 8 MB is denied before any other check (a 40 KB padded command is denied in under a second; Claude Code lets a timed-out PreToolUse hook through, so speed is the defence). `Agent` joins the matcher; PostToolUse and PostToolUseFailure hooks record spawn results.
- Invocation binding written by the guard under the plugin data folder: pending, claimed, terminal and closed records per session; one map agent at a time; `--close-session` for uncertain terminations; no foreground-less, resumed or unregistered spawns.
- Two git layers over one hardened core (`pm_git.py`, `pm-git.sh`): config, hooks, pager, fsmonitor and external diff disabled; raw `git` denied for the agent.
- Reads confined to the bound root, the plugin, agent memory and the ledger; symlinks resolved; wider secret patterns (`.git`, `.claude.json`, `*_history`, `settings*.json`, `ssh_host_*`); Grep and Glob removed from the agent.
- Signed generations: each manifest carries an HMAC, and a publish record gates adoption of a generation. The session hook injects only verified briefs.
- Secret and unicode scanning of judgement and plan text: token-like strings, control characters and bidi overrides are rejected before anything is published.
- Watch entries: relative paths only, no `..`, at most 40 entries, confined to the project root.

### Correctness
- Generation-atomic publish: immutable `gen-<seq>-<id>/`, one `current` symlink switched by atomic rename, a base check (`SUPERSEDED` when another run published first) and an OS `flock` publish lock. Crashes at any boundary leave a complete generation current.
- Watched files hashed by content with an incremental cache, partial coverage handled without spawning, `ctime` in the signature.
- `snapshot.json` (complete) separate from `pack.json` (8 KB, model-facing); `ERROR` and `REFRESH_FAILED` verdicts; strict type validation; answers tracked by line hash; brief built by priority and never cut mid-line.

### Lifecycle
- SessionStart hook injects the brief (no model call, about 300 tokens, with "N commits since"); UserPromptSubmit hook re-renders once after a plugin update, and embed acknowledges the plugin hashes at every successful publish.
- Skill rewritten: preflight, a verdict and reply table, recovery lines; unknown agent type says "run /reload-plugins".
- Agent: `maxTurns` 32, staged flow (Read pack and judgement.in, Write out files, embed), PARTIAL on any guard deny, generic "owner" wording, "3 KB target, 6 KB hard".

### Page
- The H "Neat" page: identity block, tiles, phase list with per-phase checklists, plan vs shipped, one decision panel, "A little more context"; `plan.json` with stable ids (`P1`, `P2.c3`); schema `project-map-4`; new `brief.txt` line 1.
